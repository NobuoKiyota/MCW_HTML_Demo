# ゲームデザイン基本設計

最終更新: 2026-07-27

## コアループ

1. **ミッション出撃**: 制限時間内、ミッション目標(距離/生存)を達成する
2. **戦闘**: 敵を倒すことでクレジット・改造パーツ・強化アイテムを収集
3. **Home(拠点)**:
   - 自機の改造・修理
   - 武装の購入・改造
   - 新自機の購入
4. 1に戻る(出撃)

## 自機・武装グリッドシステム

- 武器は自機の**グリッドキャパシティ内**に追加していく
- 自機・武器は**セル単位**でそれぞれ大きさが異なる
- セルの着脱・グリッド開放を行うことで、装備できる武器パターン(組み合わせ)を増やしていく

凡例: `□` = 解放グリッド(未装備) / `■` = 未解放グリッド / `●` = 武器装着

### 例1: 初期自機グリッド

```

■□□■
```

外周4マスは未解放、中央2x2(4マス)のみ解放済みの状態。

### 例2: 初期武器装備時

```

■□□■
■●●■
```

解放済みグリッドのうち下段2マスに武器(横2セル分)を装着した状態。

自機ごとにグリッドの**外形そのもの**が異なりうる(単純な矩形ではなく、機体形状に応じた不定形グリッド)。

## 技術的な接続ポイント(実装時のメモ)

- 敵・ドロップ・行動パターン等のマスタデータは `assets/Excels/*.csv` (`GameDatabase.ts` が読み込み) に集約されている。グリッド/武器マスタもこの並びに合わせて追加するのが自然。
- CSV編集は Cocos Editor拡張 `extensions/master-manager/` (Extension > Master Manager) から直接可能。
- プレイヤーの永続データ(所持クレジット・装備状態など)は `DataManager.ts` が `sys.localStorage` に保存。グリッド装備状態もここに保存対象を追加する形になる見込み。
- `game_balance.xlsm` 由来の値 (`GameBalanceData.ts`) は自動生成なので直接編集しない(リポジトリ直下 `CLAUDE.md` 参照)。

## AIからの提案(たたき台・未確定)

以下はAI側からの初期アイデアで、採用未確定です。気になるものがあれば掘り下げます。

- **武器サイズ規格**: 1x1(小型・低コスト)/1x2・2x1(中型)/2x2(重火器)くらいの粒度から始めると、グリッドパズルとしての駆け引きが早期に成立しやすい。
- **配置シナジー**: 特定の武器同士を隣接させると微ボーナス(発射レート+5%など)を与えると、ただの「空きマス埋め」で終わらず配置に戦略性が出る。
- **自機ごとの個性**: グリッド形状の違いだけでなく、特定セル位置に「特殊スロット(そこに置いた武器だけ効果アップ)」を1〜2個仕込むと、自機選びの差別化になる。
- **回転の是非**: 初期は非回転(向き固定)にして実装・UI双方をシンプルに保ち、必要なら後日回転対応を追加する方が着地しやすい。
- **グリッド解放コスト**: 単純なクレジット消費だけでなく「改造パーツ(ドロップ品)」を必須にすると、周回で集めた素材に使い道が生まれ、Home画面の周回モチベーションになる。
